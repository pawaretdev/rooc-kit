# Requirement: Map Codex — ดูมอนสเตอร์ทั้งแมพจาก modal ตัวเดียว

> สถานะ: **ร่าง (draft)** — รอ approve design ก่อนลง PLAN
> เขียนจาก brief ปากเปล่าของเจ้าของโปรเจกต์ 2026-09-20 + สำรวจโค้ด/ข้อมูลจริงในวันเดียวกัน

## 1. ปัญหา (ทำไมต้องมี)

ตอนนี้ใน `/tracker` เมื่อกด tile มอนสเตอร์ จะเปิด `MonsterDetailDialog` ซึ่งแสดง

1. **Research level** ของมอนตัวนั้น (แก้ได้ในที่)
2. **Spawn maps** — รายชื่อแมพที่มันเกิด

บล็อก spawn maps เป็น **ทางตัน**: บอกได้แค่ว่า "ตัวนี้เกิดที่ไหนบ้าง" แต่ตอบไม่ได้ว่า **ถ้าไปแมพนั้นจริง จะได้อะไรกลับมาบ้าง**

ผู้เล่นตัดสินใจโดยคิดกลับด้าน — ไม่ได้เลือก "มอนสเตอร์" แต่เลือก **"แมพ"** เพราะการฟาร์มเกิดขึ้นเป็นแมพ ไม่ใช่เป็นตัว ถ้ามอนตัวหนึ่งเกิด 3 แมพ คำถามจริงคือ *"ควรไปแมพไหน"* ซึ่งขึ้นกับว่าแมพนั้น **มีมอนอะไรอีก และแต่ละตัวเลเวลวิจัยถึงไหนแล้ว**

ทุกวันนี้ต้องปิด modal → เดาเอง → เปิด modal ตัวอื่นไล่เช็กทีละตัว

**ข้อมูลที่ต้องใช้มีอยู่แล้ว** — `monsterIdsByMapId` ใน `src/lib/game-data.ts` เป็น reverse index แมพ→มอน ที่ build ไว้ตอน import แล้ว และ key i18n `mr.detail.alsoOnMap` ("มอนอื่นในแมพนี้") ก็ถูกเพิ่มไว้ในพจนานุกรมทั้งสองภาษาแล้ว **แต่ยังไม่มีที่ไหนเรียกใช้** ฟีเจอร์นี้คือการทำส่วนที่ค้างให้จบ

## 2. สิ่งที่ต้องการ (จาก brief)

> "ถ้ามันมีหลาย maps user ก็ต้องการดูก่อนว่า map นั้นๆ มี monster อะไรอยู่ใน map บ้าง และแต่ละตัว research level เท่าไหร่แล้ว"

แตกเป็นข้อกำหนด:

| # | ข้อกำหนด | ต้องมี |
|---|---|---|
| R1 | จาก modal มอนสเตอร์ กดแมพในรายการ spawn maps แล้วดู **มอนทุกตัวในแมพนั้น** ได้ | **บังคับ** |
| R2 | มอนแต่ละตัวในแมพแสดง **research level ปัจจุบัน** (0–10) | **บังคับ** |
| R3 | แก้ research level ได้จากมุมมองแมพเลย ไม่ต้องย้อนกลับไปหาแถว | **บังคับ** |
| R4 | เห็นได้ว่ามอน "ตัวที่กดมา" อยู่ตรงไหนในแมพนั้น (ไม่หลงว่าดูแมพไหนของใคร) | **บังคับ** |
| R5 | เทียบแมพหลายอันของมอนตัวเดียวกันได้ว่า "แมพไหนคุ้มกว่า" | ควรมี |
| R6 | **modal คือแผนที่โลกจากเกม** ซูมไปที่แมพของมอนตัวนั้น | **บังคับ** |

## 3. ความจริงเรื่องข้อมูล (สำรวจแล้ว — ตัวเลขนี้กำหนดดีไซน์)

### 3.1 ข้อมูลใน tracker

| ตัวเลข | ค่า |
|---|---|
| มอนสเตอร์ทั้งหมด | 217 |
| แมพทั้งหมด | 59 |
| มอนต่อแมพ — มากสุด / กลาง / น้อยสุด | 11 / 5 / 1 |
| แมพที่มีมอนเกิน 8 ตัว | 4 |

การกระจายของ "มอนหนึ่งตัวเกิดกี่แมพ":

| เกิดกี่แมพ | จำนวนมอน |
|---|---|
| 1 แมพ | 165 |
| 2 แมพ | 33 |
| 3 แมพ | 11 |
| 4 แมพ | 6 |
| 6 แมพ | 2 |

**ข้อสรุปสำคัญ:** มอน **165 จาก 217 ตัว (76%) เกิดแมพเดียว** ฟีเจอร์นี้จึงเป็น *progressive disclosure* — คนส่วนใหญ่ไม่ได้ต้องการเทียบแมพ ดีไซน์ห้ามทำให้ modal เดิมหนักขึ้นเพื่อคน 24%

และเพราะแมพหนึ่งมีมอนมากสุดแค่ **11 ตัว** — รายการมอนทั้งแมพ **แสดงหมดได้ในหน้าจอเดียว ไม่ต้อง paginate หรือ virtualize**

### 3.2 แผนที่จาก `rooc-assets` — วางได้ครบทุกแมพ

`WorldMap_Full.png` (2048×2048) + `worldmap_cells.json` จาก Unity prefab ของเกม ช่องละ 91.34 px
ตรงกับตารางสี่เหลี่ยมขาวที่วาดอยู่ในอาร์ตพอดี

การจับคู่ 59 แมพของ tracker กับแผนที่ ทำได้ครบด้วยสามทาง:

| ทาง | จำนวนแมพ | ที่มาของพิกัด |
|---|---|---|
| มีช่องเป็นของตัวเอง | 18 | `cells[].name` ใน `worldmap_cells.json` |
| เป็นดันเจี้ยนที่มีป้ายพินอิน | 20 | `cave_labels[]` — Mayidong=Ant Hell, Jinzita=Pyramid, Jiangshidong=Payon Cave, Haididongku=Undersea Tunnel, Xiashuidao=Culvert, Oukemigong=Orc Cave, Beisen=Labyrinth Forest, Feiqikuangkeng=Mjolnir Abandoned Mine, Chenmozhichuan=Shipwreck Labyrinth |
| เป็นพื้นที่ย่อยของช่องที่มีอยู่ | 21 | Glast Heim ชั้นใน 8 แมพ, Geffen Underground 3, Payon ย่อย 3, Morroc/ทะเลทราย 4, อื่นๆ 3 |

**ไม่มีแมพไหนวางไม่ได้** — สิ่งที่ต้องทำคือ **ตาราง anchor ด้วยมือครั้งเดียว** จับคู่ 59 แมพ → พิกัด (x, y) บนแผนที่
ไม่ต้องวาดอาร์ตใหม่ ไม่ต้องใช้ `SceneMaps/` และไม่ต้องกู้ชื่อแมพภาษาอังกฤษจาก asset (ซึ่งกู้ไม่ได้อยู่แล้ว
เพราะ resolve ผ่าน localization table ตอน runtime)

**ขนาดไฟล์:** ต้นฉบับ PNG 3.5 MB ใหญ่เกินไปสำหรับเว็บ แปลงเป็น JPEG 1536px คุณภาพ 82 ได้ **652 KB**
ทดสอบแล้วภาพยังคมพอตอนซูมระดับช่อง โหลดเฉพาะตอนเปิด modal ครั้งแรกแล้ว cache ไว้

**ข้อควรระวัง:** ดันเจี้ยนหลายชั้นใช้พิกัดเดียวกัน (Pyramid F1/F2/F3 ชี้จุดเดียว) หมุดต้องเหลื่อมกันหรือรวมเป็นหมุดเดียว
ไม่งั้นจะกดตัวที่อยู่ข้างล่างไม่ได้

## 4. ขอบเขต

### ในขอบเขต

- มุมมอง "มอนทั้งแมพ" เข้าถึงจาก `MonsterDetailDialog` (ใช้ทั้งใน `RowCard` และ `TopPickCard`)
- แสดง research level ของมอนทุกตัวในแมพ + แก้ได้ในที่
- สรุประดับแมพ เพื่อตอบ "แมพไหนคุ้มกว่า" (R5)
- แสดงธาตุ / kind (MVP·Mini) / base level ของมอนแต่ละตัว
- i18n ครบทั้ง th/en (ใช้ `mr.detail.alsoOnMap` ที่มีอยู่ + key ใหม่)

### นอกขอบเขต (รอบนี้)

- ภาพแผนที่รายโซน (`SceneMaps/`) — ใช้แค่ world map ใบเดียว
- แผนที่ Miao (ทะเล) — ยังไม่มีแมพใน tracker ที่อยู่โซนนั้น
- หมุดของแมพที่มอน "ตัวอื่น" เกิด — รอบนี้แสดงเฉพาะแมพของมอนที่เปิดมา
- หน้า `/maps` แยกเป็น route ของตัวเอง — ถ้าอนาคตต้องการ ค่อยยกส่วนนี้ไปใช้ซ้ำ
- เปลี่ยนโครง `MapFilter` ที่มีอยู่

## 5. ข้อจำกัดเชิงเทคนิค

- **ไม่ต้องแตะ data layer ฝั่งมอนสเตอร์** — `monsterIdsByMapId` มีแล้วใน `game-data.ts`
- **ต้องเพิ่มไฟล์ข้อมูลใหม่หนึ่งไฟล์** — ตาราง anchor (แมพ → พิกัดบนแผนที่) เข้า `src/data/` และต้องผ่าน `pnpm data:check`
- **ภาพแผนที่** เสิร์ฟผ่าน `src/lib/images.ts` ตามกติกาเดิม (รองรับ `NEXT_PUBLIC_IMAGE_CDN`) ห้าม import ตรง
- **ไม่แตะ schema / ไม่ sync เพิ่ม** — อ่าน level จาก Dexie ที่โหลดอยู่แล้ว เขียนผ่าน `setMonsterLevel` ตัวเดิม (auto-sync ทำงานต่อเอง)
- **ทำงานแบบ local-first** — ไม่ต้อง sign-in
- ทุก state ใหม่เป็น state ใน component ไม่เก็บลง storage
- ต้องผ่าน `pnpm lint` + `pnpm build` + `pnpm test`
- เคารพ DESIGN.md: ไม่มี `rounded-full`, ตัวเลขเป็น `font-mono tabular-nums`, accent = ส้มจุดเดียว, ทอง = ความคืบหน้า, แดง = blocker เท่านั้น, ไม่มีเงาบนการ์ดปกติ

## 6. เกณฑ์ยอมรับ

1. เปิด modal มอนที่เกิดหลายแมพ → กดแมพใดก็ได้ → เห็นมอนทุกตัวในแมพนั้นพร้อมเลเวล
2. มอนที่กดเข้ามาถูกทำเครื่องหมายชัดเจนในรายการ (R4)
3. เพิ่ม/ลดเลเวลจากมุมมองแมพ → ตัวเลขอัปเดตทันที และสะท้อนที่ tile ในแถวหลังปิด modal
4. มอนที่เกิดแมพเดียว (76%) ต้องไม่รู้สึกว่า modal ยุ่งขึ้นกว่าเดิม
5. แมพที่มีมอน 11 ตัว แสดงครบโดยไม่ต้องเลื่อนในแนวที่อึดอัด
6. ใช้ได้บนมือถือ — hit target ≥ 44px ตามกติกา touch ใน DESIGN.md
7. ไม่มีสตริงฮาร์ดโค้ด — ผ่าน `useT()` ทุกจุด
8. `pnpm lint`, `pnpm build`, `pnpm test` ผ่าน

### ไฟล์ที่แก้

- `src/lib/game-data.ts` — `GameMap.anchor` + type `MapAnchor`, export `worldMapCellSize` / `worldMapImageFile` (เก็บพิกัดเป็นสัดส่วน 0..1 จะได้ไม่ผูกกับขนาดภาพ)
- `src/lib/images.ts` — `worldMapImageUrl()` ตามกติกา CDN เดิม
- `src/lib/i18n/messages.ts` — 27 key ใหม่ ครบทั้ง th/en
- `src/components/icons.tsx` — `SearchIcon`, `FitIcon`
- `src/features/monster-research/MonsterDetailDialog.tsx` — ปุ่ม "ดูบนแผนที่โลก" + แถวแมพกดเข้าได้
- `scripts/validate-data.mjs` — **บังคับ**ว่าทุกแมพที่มีมอนเกิดต้องมี anchor ไม่งั้น `pnpm data:check` ล้ม
- `src/lib/game-data.test.ts` — เทสต์ว่า anchor ครบ 59 แมพและอยู่ในกรอบ 0..1

### พฤติกรรมที่ได้

- กด tile มอน → modal เดิม → ปุ่ม "ดูบนแผนที่โลก" → แผนที่เปิดมาซูมกรอบทุกแมพของมันให้พอดีอยู่แล้ว
- rail ซ้ายเลือกมอนได้ ค้นหาได้ กรองธาตุและ MVP/Mini ได้ ตัวที่เลือก**เอียงซ้าย 9°** + มี**หมุดมุมขวาบน** + พื้นส้ม
- ทุกแมพที่มอนเกิด**ไฮไลต์เป็นกรอบ** (ส้ม / ทองเมื่อเต็มแล้ว) และมี**สไปรต์มอนตัวนั้นทับอยู่** พร้อมตัวนับ `เต็ม/ทั้งหมด`
- ขวาแสดง**รายชื่อมอนในแมพนั้นพร้อมเลเวลวิจัย** แก้ได้ในที่ เขียนลง Dexie ทันที (ยืนยันจาก IndexedDB จริงแล้ว)
- ดันเจี้ยนหลายชั้นพิกัดเดียวกันรวมเป็นหมุดเดียว ("Pyramid · 2 ชั้น") แล้วแตกเป็นชิป F1/F2 ในพาเนล — แก้ปัญหาที่ชั้นล่างกดไม่ได้
- มือถือยุบเป็นสามแท็บ: มอนสเตอร์ / แผนที่ / ในแมพนี้
