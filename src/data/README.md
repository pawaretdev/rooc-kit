# Static Game Data — Authoring Guide

คู่มือกรอกข้อมูล Monster Research สำหรับคนเตรียมไฟล์ (กรอกมือจากในเกม)

## โครงสร้างไฟล์

```
src/data/
├── meta.json            # version ของชุดข้อมูล — bump ทุกครั้งที่แก้ข้อมูล
└── research/
    ├── neutral.json     # หนึ่งไฟล์ต่อหนึ่งธาตุ
    ├── water.json
    └── ...
```

ชื่อไฟล์ = ชื่อธาตุตัวพิมพ์เล็ก เรียงตามลำดับ sidebar ในเกม (UI ก็เรียงตามนี้):
`neutral` `wind` `earth` `fire` `water` `poison` `holy` `shadow` `ghost` `undead`

> ในเกม (client ไทย) ธาตุแรกแสดงเป็น "None" แต่ canonical id ของเราคือ `Neutral` — UI จะแสดง label ตามเกมเองทีหลัง

## Schema ต่อไฟล์

```jsonc
{
  "element": "Neutral",        // ตรงกับชื่อไฟล์ ตัวพิมพ์ใหญ่ขึ้นต้น
  "rows": [
    {
      "row": 1,                // ลำดับแถวในธาตุ เริ่มที่ 1 เรียงตามในเกม
      "monsters": [
        {
          "name": "Lunatic",        // ชื่อภาษาอังกฤษตามในเกม — ใช้เป็น id จึงต้องสะกดเหมือนกันทุกที่
          "type": "Normal",         // "Normal" | "Mini" | "MVP"
          "baseLevel": 5,           // เลเวล monster ในเกม (ไม่ใช่ MR level!)
          "locations": [            // ชื่อแมพที่เกิด สะกดให้เหมือนกันทุกไฟล์
            "Prontera North Gate"
          ]
        }
      ]
    }
  ]
}
```

## กติกาสำคัญ

- **ชื่อในไฟล์เป็นภาษาอังกฤษเท่านั้น ไม่มีชั้นแปล** — UI ของแอปมี 2 ภาษา (th/en) แต่แปลเฉพาะข้อความ UI ชื่อ monster / แมพ / ธาตุแสดงเป็นอังกฤษเสมอเพราะใช้เป็น id
- **สะกดชื่อให้ตรงกันเสมอ** — ทั้งชื่อ monster และชื่อแมพจะถูกแปลงเป็น id อัตโนมัติแบบ kebab-case (`"Peco Peco Egg"` → `peco-peco-egg`) สะกดต่างกันนิดเดียว = กลายเป็นคนละตัว/คนละแมพ
- **id = ชื่อไฟล์รูปบน CDN** — รูป monster ที่ extract จากเกมตั้งชื่อเป็น kebab-case อยู่แล้ว แอปจะประกอบ URL เป็น `<CDN>/<id>.png` ตรง ๆ ถ้าตัวไหนชื่อไฟล์รูปไม่ตรงกับ id ที่ derive จากชื่อ ให้เพิ่ม field `"image": "ชื่อไฟล์จริง"` ทับเฉพาะตัวนั้น
- **`baseLevel` คือเลเวลของ monster ในเกม** ไม่เกี่ยวกับ MR level (0–10) ที่ user กรอกเอง — มีไว้แสดงใน UI ช่วยประเมินว่าจะฆ่าตัวนี้เร็วหรือช้า (มีผลต่อความเร็วในการดัน MR) เท่านั้น
- แถวที่ตอนนี้มี monster ไม่ครบ 5 ตัว (เช่น Neutral row 4) เป็นเรื่องปกติ — เกมเปิดแมพใหม่แล้วอาจเพิ่มเข้ามาทีหลัง
- ชื่อแมพที่มีหลายชั้นใช้ format `F1` `F2` `F3` ต่อท้าย เช่น `Pyramid F3`
- แถวที่ยังเปิดไม่ครบ/มี monster ไม่ครบ ให้ใส่เท่าที่รู้ไว้ก่อนได้ แล้วค่อยเติมทีหลัง (bump `version` ใน meta.json เมื่อเติม)
- User progress (MR level ที่ user กรอก) **ไม่อยู่ในไฟล์พวกนี้** — อยู่ใน browser storage แยกต่างหาก

## ตรวจข้อมูลหลังกรอก

```bash
pnpm data:check
```

เช็ค schema, ชื่อ monster ซ้ำข้ามไฟล์, และชื่อแมพที่สะกดเพี้ยนกัน (เช่น เว้นวรรค/ตัวพิมพ์ต่างกัน) — รันทุกครั้งหลังกรอกเสร็จหนึ่งธาตุ
