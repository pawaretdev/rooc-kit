# ROOC Kit

Companion web app for **Ragnarok Origin Classic** — helps players plan daily farming (Monster Research tracker) and get card-market restock alerts. The game exposes no public API, so all data is manual-entry; the app is client-side and privacy-first. Monster Research is the first tool, not the only one planned.

## Commands

- `pnpm dev` — dev server (Next.js, http://localhost:3000)
- `pnpm build` — production build
- `pnpm lint` — ESLint
- `pnpm data:check` — validate static game data (run after any edit under `src/data/`)
- `pnpm test` — Vitest (`src/**/*.test.ts`)
- `pnpm db:generate` / `pnpm db:migrate` — Drizzle migrations (need `DATABASE_URL`)

## Stack (actual)

Next.js 16.3.0 (App Router, `src/app/`), React 19, TypeScript, Tailwind CSS v4 (PostCSS plugin, no tailwind.config), pnpm.

Installed and in use (2026-08-10): Dexie (local progress, `src/lib/local-db.ts`), Drizzle ORM (Railway Postgres, `src/lib/db/`), Auth.js/NextAuth v5 (Discord + Google, JWT sessions, `src/lib/auth.ts`), shadcn/ui components bridged to the app's design tokens (`src/components/ui/` + token bridge in `globals.css`). Deploy targets: Vercel (app) + Railway (Postgres, later the alert cron). Full stack table and reasoning: README *Tech Stack* + `docs/PROPOSALS.md` §4.

Before touching Monster Research logic, read README's *Game Mechanics Reference* and *Data Model*. Core rules:

- A **row's level is the minimum monster level in it** (a row at `4,5,5,6,7` is level 4) — but **only rows with all 5 monsters have a level**; rows with fewer (incomplete data) have no row level, no blockers, and never count as completed (`ROW_SIZE` in `rowStats.ts`).
- **Blockers** are the monsters sitting at that minimum — they hold the row back.
- Monster levels cap at 10. A monster can spawn on multiple maps (`mapIds` is an array).

## Architecture principles

- Local-first: the tracker is fully usable client-side without an account. The server layer is Next.js route handlers / server actions used **only** for auth (Auth.js) and progress sync (Railway Postgres via Drizzle); the market-alert cron (Phase 3) is a small service on Railway. Never require sign-in for core features.
- Two data layers, never mixed:
  - **Static game data** — monsters/rows/elements/maps as versioned JSON in the repo.
  - **User progress** — MR levels and settings in browser storage, exportable/importable as JSON.
- Privacy stance: never read game memory, automate in-game actions, or upload user data (except a user-supplied Discord webhook URL).
- Every future import path (spreadsheet paste, OCR, desktop helper) must converge on one shared JSON schema so the web app has a single import endpoint.

## Conventions

- Planning docs are written in Thai; code, identifiers, and commit messages are in English. Respond to the user in Thai.
- **UI is bilingual (th/en, default en)** — every user-facing string goes through `useT()` from `src/lib/i18n` (add the key to both dictionaries in `messages.ts`); never hardcode UI text. Monster/map/element names are canonical English ids and are **never** translated.
- **Production grade is a requirement, not a wish** — this deploys to real users:
  - All DB access goes through one shared Drizzle client module (small pool — Railway Postgres has a low connection limit and Vercel functions are serverless). Auth.js stays on JWT sessions so ordinary requests never open a DB connection.
  - Schema changes only via committed `drizzle-kit` migrations; never hand-edit the database.
  - Secrets only in env vars; validate required env at startup; nothing secret in the repo.
  - `pnpm lint` and `pnpm build` must pass before any commit; `pnpm data:check` after touching `src/data/`. Set up Vitest alongside the first non-trivial logic (row stats), not "later".
  - Handle the unhappy paths you create: loading/error states for async UI, try/catch with user-visible feedback on sync/auth failures, no silently swallowed promises.
- Decisions live in docs, not in chat: resolved questions graduate from `docs/OPEN-QUESTIONS.md` → `docs/PROPOSALS.md`/`README.md`. Keep them in sync when a decision is made.

The **World Map** (`src/features/world-map/`) is both its own page at `/world-map` (a navbar tab, behind `AuthGate`, sized `h-[calc(100svh-3.5rem)]` because the page body is only `min-h-full`) and a near-fullscreen modal reached from a monster's detail dialog via "View on world map" (or by clicking a row in *Spawn maps*, which opens straight onto that map). Both mount the same `WorldMapBody`; the page omits `onClose`, which is what drops the close button and swaps the Radix title for a plain heading. It shows — monster picker rail on the left (search + **base-level brackets** + Normal/Boss filters; the chosen one gains an accent fill and a pin badge), the game's world map in the middle, and the selected map's full roster with editable research levels on the right. **Every cell is clickable**, not just the selected monster's, so the map can be browsed on its own. Cell states are two different things and never share a look: a **spawn** of the selected monster is a **dashed gold** box holding the plain sprite (no research frame, no tilt — the tilt belongs to the picker), while the **open** cell is a **solid accent** box with a ring. Each cell carries its map name in its own footer, faint by default and solid once the cell is a spawn or the open one. The box lives in map space so it always covers its painted square, and **its sprite and label are sized as a share of the cell** (58% / 13.5%) so they grow and shrink with the square that frames them. Only the border width is corrected (`2/scale`), because a plain `border-2` is multiplied by the camera and reads as a 9px slab at 460%. That border's *style* is set inline, not as a Tailwind class: `border-dashed` and `border-solid` have equal specificity, so whichever ships last silently wins and the dashes disappear. Clicking the pinned monster again unpins it: the map then shows no sprites and no dimming. Anchors live in `src/data/world-map.json`, generated by `node scripts/build-world-map.mjs` from the extracted prefab — **never hand-edit it**; every map binds to a real prefab cell id, which is what keeps tiles on the grid painted into the art (the prefab's `cave_labels` are captions drawn *beside* their entrance, so using them directly lands off-grid). Maps sharing a cell share one pin and are picked in **two steps** in the panel — place first, then floor, because one cell can hold nine maps (Glast Heim and its interiors) and a single row of nine tabs is unreadable; the floor row only appears when the chosen place has floors. The map whose anchor `source` is `cell` — the place the square *is* — leads and names the pin, so Glast Heim is not renamed "Catacomb" just because that sorts first: dungeon floors, a dungeon and the field above it (Orc Cave + Orc Village, Prontera West Gate + Culvert), and the eight Glast Heim interiors (all `cave:` sourced — Glast Heim is the place you walk to, the rest are entered from it). A **Show caves** button mirrors the game's own world-map control: it *reveals* the names of the dungeons tucked inside cells (Culvert inside Prontera West Gate, "Pyramid · Sphinx Crypt" in one square), it does not hide anything. **Each dungeon gets its own label and its own arrow-tipped leader line** (`MapPin.callouts`, placed by `assignCallouts` in `allPins`) — Glast Heim hides six, and one shared line said nothing about which is which. Labels float free at any offset, diagonal or several cells out, and are kept off squares that hold maps, off each other, and inside the framed area; because a label is wider than one square, the placer reserves the whole strip it covers rather than just its centre. One cell's labels are **fanned around it** and held ~25° apart — letting each grab the nearest free slot sent them all the same way and tangled the lines. Each line starts at its label's real box edge, computed from the text width: a fixed gap from the label's centre left the first stretch hidden under a wide chip, so the arrow looked detached from the name — Culvert and Ant Hell point sideways for exactly that reason. Off by default so the map starts uncluttered. Selecting a cell does **not** move the camera — yanking the view away from what the user is reading is worse than making them pan. Cells the monster spawns in are lit against a dimming layer over the rest of the map. `pnpm data:check` **fails** if any spawn map lacks an anchor. Pure logic + tests in `mapGroups.ts`; pan/zoom in `useMapCamera.ts` (opens at 120%, and map tiles scale *with* the camera rather than counter-scaling, or they drift off their cells).
